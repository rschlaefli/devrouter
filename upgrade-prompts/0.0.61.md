# Upgrade to devrouter 0.0.61

This patch keeps manual ensure and exec usable after settled operation history
reaches its bound. Managed Devsy startup records exact stop ownership before
application readiness on supported local Unix Docker endpoints. With that recorded
baseline, ordinary stop tolerates changed or missing repository configuration
without deleting containers or volumes.

## Task

Install the published patch through the established consumer workflow and update
`.devrouter.yml` devrouter.version to 0.0.61. No repository schema migration is
required. Refresh distributed agent guidance through the established workflow.

Use canonical ensure, exec and stop for the authorized exact checkout. Stop
baselines are captured by a qualifying startup; installation alone does not create
them for older runtimes. Do not fabricate ownership records or replay a failing
post-create hook to obtain a baseline.

## Validation

Verify installed version, exact checkout/profile and provider identity. For a
baseline-backed runtime, verify stop after configuration drift, retained-data
resume, and final stopped provider state with zero exact routes. Keep existing
passing evidence only where source, toolchain and relevant environment agree.

## Limits

Legacy records without a baseline retain the existing configuration-dependent
stop path. Other recognized Docker transports retain legacy behavior with a
notice. Invalid or mismatched ownership does not fall back to weaker proof.
This patch does not repair repository bootstrap/database errors, establish data
preservation after a destructive hook, prevent every provider replacement, enable
capacity admission, or provide complete OOM protection or autonomous recovery.

## Report

Report installed version, exact checkout/profile, whether a stop baseline existed,
checks performed, retained-data evidence, final provider and route state, and any
remaining recovery limitation. Distinguish fixture proof from consumer acceptance.
