# Upgrade to devrouter 0.0.47

Devrouter now prepares and verifies the Devsy agent before managed workspace
startup instead of relying on Devsy's opaque start-time acquisition.

1. Install `@devrouter/cli@0.0.47` on the host and bump `.devrouter.yml` to
   `devrouter.version: 0.0.47`.
2. When Devsy is the selected workspace runtime, run
   `devrouter setup --yes --workspace-runtime devsy` once. This is the only
   normal workflow step that downloads the supported agent. Direct HTTPS is
   primary; when that connection fails, an authenticated `gh` can stream the
   same pinned release asset through GitHub's API.
3. Run `devrouter doctor --repo <checkout> --json`. Require the
   `global.devsy-agent` check to report `ready` before starting a workspace.
   `missing`, `stale`, and `invalid` states include the exact setup repair and
   never perform network access.
4. Keep using `devrouter ensure <checkout>`. A non-ready agent now fails before
   the provider queue, registry reads, or workspace mutation.
5. If `DEVSY_AGENT_BINARY` is set, either point it at a matching pinned
   official asset or unset it and rerun setup. Devrouter never replaces an
   explicit source.
6. The desktop app and CLI continue to share Devsy's workspace registry.
   Devrouter passes its verified agent only to the starting CLI child; it does
   not modify Devsy's private cache or the desktop app environment.

Verification:

- Run `devrouter -V --repo <checkout>` and confirm the installed CLI and local
  repository report `0.0.47`.
- Run `devrouter setup --yes --workspace-runtime devsy --json` and require the
  `global.devsy-agent` action to succeed.
- Run `devrouter doctor --repo <checkout> --json` and require
  `global.devsy-agent` to report `ready` without a filesystem path.
- Run one representative `devrouter ensure <checkout> --json` only when the
  workspace is safe to start, then stop the exact checkout through Devrouter.
