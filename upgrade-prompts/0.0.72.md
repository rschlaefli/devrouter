# Upgrade to devrouter 0.0.72

This patch release lets capacity-enrolled checkouts keep working past the
128-entry lifecycle journal cap. Previously the journal refused every later
`ensure` and `exec` once it filled, because history rollover ran only under
manual execution policy. Enrolled repositories now roll over under the same
conservative guards as manual ones. No schema, configuration, or CLI flag
changes.

## Task

Install the published release and update `.devrouter.yml` devrouter.version to
0.0.72. No configuration change is required.

## Validation

On a repository with an enabled capacity policy enrollment whose journal is at
or near its cap, run `devrouter ensure <path> --json` and confirm the operation
is admitted and dispatched instead of failing with a blocked lifecycle
transition. `devrouter exec <path> -- echo ok` must complete, and
`devrouter stop <path>` must end with the runtime stopped and zero routes.

## Report

Report the installed CLI version, the enrolled repository, the journal entry
count before and after the operation, and the final stopped status with the
route count.
