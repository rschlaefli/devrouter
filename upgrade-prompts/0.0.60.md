# Upgrade to devrouter 0.0.60

This patch retains a coherent degraded candidate after an external reset and
failed recreation when exact ownership, complete service population and unchanged
configuration are proven. Existing ordinary ensure can recover that record.
It also includes foreground controller observation of independent infrastructure
and application readiness, with bounded subscriptions and durable session fencing.

## Task

Install the published patch through the existing consumer workflow and update
`.devrouter.yml` devrouter.version to 0.0.60. No schema migration is required.
Refresh distributed agent guidance with the repository's established workflow.
Use ordinary ensure on the authorized exact checkout; preserve data and recorded
ownership. Never manufacture fingerprints or adopt another checkout's containers.

## Validation

Verify the requested profile, exact provider/container ownership, preparation and
application readiness separately. If recreation fails, inspect whether the exact
candidate was proven and retained as degraded. Retry ordinary ensure through its
supported recovery path. Incomplete proof remains an explicit diagnostic.

For ongoing observation, use the documented foreground controller session flow;
verify infrastructure readiness remains distinct from an application error.
Stop the exact task runtime after qualification and verify stopped provider state
and zero exact routes, retaining data.

## Limits

Source and installed synthetic-provider tests cover these contracts. They do not
prove the original other-host reset incident, complete OOM protection, capacity
admission or autonomous agent recovery. Controller observation does not repair or
schedule workloads. Live acceptance requires the existing runtime owner's evidence.

## Report

Report installed version, exact checkout/profile, ownership and recovery results,
application versus tooling readiness, retained data and final stopped/route state.
Identify incomplete or synthetic-only evidence without expanding release claims.
