# Upgrade to devrouter 0.0.77

Ordinary ensure now prepares TLS coverage for resolved HTTP and TCP proxy hosts
before provider startup and container-side repository hooks. The existing
certificate lock preserves coverage for other checkouts. Late publication checks
remain, and retained-runtime repair keeps its infrastructure-free behavior.
No schema, command, flag, or environment-variable migration is needed.

## Task

Use the published 0.0.77 CLI. Update `.devrouter.yml` devrouter.version only when
consumer source changes are authorized. Preserve staged work owned by another
task. Refresh generated agent guidance only with the repository owner's authority.
No generated runtime configuration or journal rewrite is needed.

For an affected checkout, retain one owner for its supported ensure/check/stop
sequence. Historical degraded state can select retained-runtime repair, which
skips shared infrastructure. If certificate coverage is missing, reconcile it
through the supported TLS setup or refresh path with the relevant machine-change
authority; do not bypass TLS verification or repeat lifecycle mutations blindly.

## Validation

Verify the installed version and exact checkout ownership. Check that the served
certificate validates the resolved hostname using the trusted local CA; certificate
file coverage alone does not prove live serving. Verify application readiness
separately. Finish with canonical stop and exact provider-stopped/zero-route proof
unless the owner explicitly retains the runtime. Preserve live-worker, ownership,
configuration and surviving-resource refusals.

## Report

Report release revision, installed executable, exact checkout and producing-run
results. Separate source/CI and TLS proof from application readiness and runtime
shutdown. A trusted TLS handshake or an HTTP404 is not successful app recovery.
