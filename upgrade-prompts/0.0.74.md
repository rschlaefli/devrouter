# Upgrade to devrouter 0.0.74

This patch fixes canonical stop after managed Devsy startup fails before
registration, including Devsy-only installations without the legacy DevPod CLI.
It preserves completed startup outcomes and refuses unknown ownership, live
workers, surviving containers (including stopped containers), and routes.
No configuration schema, command, or flag migration is required. Successful
absence proof is reported as `runtimeAbsent: true` in stop JSON.

## Task

Use the published 0.0.74 CLI. Update `.devrouter.yml` devrouter.version to 0.0.74
when consumer source changes are authorized; preserve another task's staged
work. No DevPod installation or runtime-selection change is needed. Refresh
generated agent guidance only when that repository's owner authorizes it.

For an affected exact linked checkout, use canonical `devrouter stop <path>
--json`. A completed journal alone is not evidence that resources are absent;
do not edit lifecycle state or delete provider data to bypass a refusal. This
fix does not recover retained-container identity drift or replace surviving
resources.

## Validation

Verify the CLI version and exact checkout ownership. Run the supported stop
under the checkout owner's recovery authority. Require successful absence proof
and settled lifecycle state before retrying ensure. Revalidate the original port
conflict before that retry, then require provider, application and route proof.
Do not infer consumer recovery from package or regression tests.

## Report

Report the installed CLI version and release revision, exact checkout, stop
result, lifecycle state, subsequent ensure and route/application evidence, or
the precise fail-closed blocker. Confirm source/index and runtime data retention.
