# Upgrade to devrouter 0.5.0

This minor release makes devrouter the owner of idle stop for managed
devcontainer environments.

- `devrouter workspace idle [--repo <path>] [--idle-for 30m] [--json]` reports
  each running managed environment as `active`, `idle`, `unknown` or
  `protected` and changes nothing. `--stop` stops only `idle` environments
  through the normal `stop` path.
- `devrouter setup --yes --idle-stop <duration|off>` installs or removes a
  macOS launchd agent that runs the sweep every five minutes.
- `devrouter workspace pin [path] [--off]` keeps one environment running
  regardless of activity.
- Devsy workspaces now start with an empty `INACTIVITY_TIMEOUT`, which disables
  Devsy's own idle daemon. `--devsy-inactivity-timeout` and a stored
  `devsyInactivityTimeout` are deprecated and ignored.
- `devrouter stop <path>` on a linked worktree devrouter never started now
  exits 0 with nothing to stop.

Idle stop is opt-in per machine. Nothing stops automatically until a person
runs `setup --idle-stop`. There is no configuration change and no migration.

## Task

Install the published 0.5.0 CLI. No repository change is needed. A repository
that requires 0.4.x keeps working with 0.5.0. Bump a repository's
`devrouter.version` to 0.5.0 only when consumer source changes are authorized.
Do not run `setup --idle-stop` on a person's machine without their request.

Repositories whose developers rely on database-only sessions should mention
`devrouter workspace pin .` in their contributor docs, because TCP traffic is
not observed as activity.

## Validation

1. Run `devrouter -V` from the consumer checkout.
2. With the runtime running, run `devrouter workspace idle --repo . --json` and
   confirm the checkout is listed with readable signals.

## Report

Report the release revision, the resolved executable with its installed
version, and the checkout's idle status and any `unknown` reason.
