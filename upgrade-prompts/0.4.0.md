# Upgrade to devrouter 0.4.0

This minor release adds `devrouter env`, which gives host-run tools such as
Playwright, `psql` or Prisma the endpoints of a checkout's managed runtime.

- `devrouter env [path] [--json]` reports the checkout's routed HTTPS URLs,
  the routed TLS/SNI and published loopback endpoints of its TCP apps, the
  workspace token and the mkcert CA path. The JSON report has `version: 1`.
- `devrouter env [path] -- <command...>` runs a host command without a shell.
  It exports `DEVROUTER_WORKSPACE`, `DEVROUTER_<APP>_URL`,
  `DEVROUTER_<APP>_HOST`/`_PORT` (loopback) and
  `DEVROUTER_<APP>_ROUTED_HOST`/`_ROUTED_PORT`, plus `NODE_EXTRA_CA_CERTS`
  when it is unset, and returns the command's exit code.

The command only reads state. It never starts or stops a runtime and prints no
credentials. A loopback endpoint is reported only when exactly one running
container of this checkout's devcontainer owns the upstream alias and
publishes the port on a loopback address; otherwise the report names the
reason. There is no configuration change and no migration.

## Task

Install the published 0.4.0 CLI. No repository change is needed. A repository
that requires 0.3.x keeps working with 0.4.0. Raise a repository's documented
minimum devrouter version to 0.4.0 only when consumer source changes are
authorized and a host script should use `devrouter env` instead of its own
port discovery.

## Validation

1. Run `devrouter -V` from the consumer checkout. A repository Volta pin can
   change which install resolves.
2. With the runtime running, run `devrouter env . --json` and confirm the app
   URLs and loopback ports match `devrouter status` and `docker port`.

## Report

Report the release revision, the resolved executable with its installed
version, and any loopback reason other than a running endpoint.
