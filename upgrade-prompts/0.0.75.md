# Upgrade to devrouter 0.0.75

This patch fixes canonical stop after initial managed Devsy startup is cancelled
before managed runtime state is saved. Stop uses the exact drained ensure's
recorded profile and validates complete live ownership and Compose configuration
hashes. No configuration schema, command, flag or runtime-provider migration is
required.

## Task

Use the published 0.0.75 CLI. Update `.devrouter.yml` devrouter.version to 0.0.75
only when consumer source changes are authorized. Preserve staged work owned by
another task. Refresh generated agent guidance only with the repository owner's
authority. No DevPod installation is needed.

For an affected exact checkout, use `devrouter stop <path> --json` with the same
non-secret Compose inputs used at startup. Existing interrupted workspaces can
recover when the exact operation history and all live configuration and ownership
proofs remain available. Missing, unreadable, conflicting or changed evidence
remains a refusal; never fabricate journal state or replace the selected profile
with the default to bypass it. Stop is non-destructive and retains volumes.

## Validation

Verify the released CLI revision and exact checkout ownership. Let the checkout's
runtime owner perform the canonical stop, require provider cessation and route
removal proof, then verify stopped lifecycle state. Revalidate port conflicts
before a new ensure and require its own provider, application and route proof.
A successful stop or source test does not prove successful application startup.

## Report

Report release version/revision, exact checkout, producing stop result and
lifecycle state, subsequent ensure evidence or precise refusal, and source/index
preservation. Separate released source from live consumer acceptance.
