# Upgrade to devrouter 0.0.73

This patch release adds opt-in bounded automatic recovery and fixes three
capacity-managed defects found while dogfooding the eLearning canary.

- Capacity-enrolled `exec` now returns the wrapped command's output. The
  controller captured a supervised worker's stdout and stderr into its bounded
  buffer and the client exposed it through `onOutput`, but the CLI never
  forwarded it, so `devrouter exec <path> -- <command>` returned only the exit
  status. The controller-supervised path now streams each bounded page to the
  caller and prints one notice if the buffer dropped earlier bytes.
- A capacity-enrolled operation keeps its effect authority while the controller
  cannot observe capacity. Renewal previously wrote a zero deadline before each
  attempt and again on failure, so one missing, stale, or unknown sample revoked
  authority mid-start and later commands failed with `Capacity effect authority
  is absent or stale.` Renewal now extends only when every reserved domain has a
  usable sample. Ownership evidence also compares environment identity instead
  of whole journal records, so the controller rewriting its own bookkeeping no
  longer reports `unknown` for a healthy runtime.
- The observation collector reports a required managed process that has
  positively exited as a failed capability instead of `unknown`, so bounded
  recovery can act on it. Ambiguous or unreadable process state stays `unknown`.
- Optional bounded automatic recovery. A new `recovery` block in the capacity
  policy enables a supervisor that reacts to a positively failed required
  capability with one journal-admitted corrective `ensure`, bounded by
  per-scope restart counts, an aggregate corrective-action cap and a rolling
  observation window. The block is absent by default. Parking and controlled
  resume remain model-only, and there is no OOM detection: a container-local OOM
  still surfaces only as a failed capability.

No `.devrouter.yml` schema, CLI flag, or default behavior changes.

## Task

Install the published release and update `.devrouter.yml` devrouter.version to
0.0.73. No configuration change is required. Enabling bounded recovery is
optional: add a `recovery` block to the operator capacity policy only when you
want automatic corrective ensures.

## Validation

On a capacity-enrolled checkout, run
`devrouter exec <path> -- bash -lc 'echo checked'` and confirm the command's
output appears. Confirm a failing command still returns its non-zero exit
status, and that `devrouter ensure <path>` reports the environment ready with
its routes published. If you enabled recovery, confirm an environment whose
required process is positively absent is corrected by one admitted `ensure`
within the configured bound.

## Report

Report the installed CLI version, the enrolled repository, the observed `exec`
output and exit code, the final `ensure` readiness with its route count, and
whether the recovery policy was enabled.
