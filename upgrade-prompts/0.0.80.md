# Upgrade to devrouter 0.0.80

This release makes Devsy maintenance routine instead of disruptive. Devrouter
now supports installed Devsy releases in the range `>=1.16.2 <2.0.0`: an
explicit `setup --workspace-runtime devsy` verifies the official Linux agent
for the installed release against the SHA-256 digest GitHub publishes, records
the manifest in Devrouter machine state, and injects it, while `doctor` and
`ensure` stay network-free. An in-range release with no recorded manifest is
accepted with a drift warning and nothing injected, so a Devsy update no longer
blocks a managed start. The release also reworks the harness gate wait budget,
adds a `devrouter capacity reconcile` recovery, names the router holder in
host-port conflicts, accepts worktree-owned dependency-overlay upstreams, and
adds the `global.cli-path` install comparison to `doctor`.

## Task

Use the published 0.0.80 CLI. Update the repository `devrouter.version`
metadata only when consumer source changes are authorized, and refresh generated
agent guidance only with its owner's authority. No schema, journal or
configuration migration is needed.

Operating changes that matter for scripts, agents and operators:

- **Devsy agent.** Run `devrouter setup --yes --workspace-runtime devsy` once
  per installed Devsy release, and rerun it after a Devsy update, to verify and
  inject the official agent for that release. Until a release's manifest is
  recorded, `doctor` reports `ready` with a drift warning and
  `source=host`: the host CLI governs its own agent and Devrouter injects
  nothing. A version outside the supported range, or an unparseable one, still
  fails before the provider queue, and an explicit `DEVSY_AGENT_BINARY` must
  match the official asset for the installed release.
- **Harness gate.** A `PreToolUse` hook timeout must exceed
  `--wait-budget-ms`. The budget now measures only the actual wait, and a call
  the harness re-delivers with the same `tool_use_id` returns one refusal that
  names the earlier decision instead of waiting again.
- **Capacity recovery.** `devrouter capacity reconcile --yes` replaces a
  provably absent ledger with a fresh baseline. It refuses without `--yes` and
  while any journal binding remains; treat it as operator recovery, not routine
  maintenance.
- **Multiple installs.** `doctor` reports `global.cli-path`. Upgrade every
  `devrouter` install on PATH so a stale binary cannot run lifecycle rules
  against state a newer version wrote.

## Validation

Confirm the resolved executable and installed version from a consumer checkout,
and check `global.cli-path` reports no stale or divergent install. Confirm
`global.devsy-agent` reports `ready`; before `setup` records the installed
release, expect the non-blocking drift warning, and after it expect the recorded
manifest with no network access at `ensure` time. Parse command JSON from
stdout only, because `ensure` and `stop` still stream bounded phase progress
on stderr. Exercise `capacity reconcile` or a stuck `stopping` settlement
only with operator authority, and require each operation's own terminal
evidence.

## Report

Report the release revision, resolved executable, installed version, the Devsy
agent and `global.cli-path` diagnostics, the manifest origin reported after
`setup`, and the terminal result of any authorized lifecycle or capacity
operation. Keep source and package validation separate from consumer readiness,
and record unknown ownership or ledger evidence as unresolved rather than as
recovered.
