# Upgrade to devrouter 0.5.3

This patch release supports verified Devsy agents on Linux arm64/x64,
custom DevPod and Devsy runtime homes, and drainage of Linux process groups
proven to contain only zombies. There is no configuration schema migration.

## Task

Install the published 0.5.3 CLI. Bump a consumer's `devrouter.version` only when
consumer source changes are authorized. Preserve exact checkout ownership,
containers, databases, dependency volumes, and existing runtime directories.
Changing the machine preference does not migrate a DevPod-owned checkout.

For Devsy, run `devrouter setup --yes --workspace-runtime devsy` to verify the
installed release's official Linux agent. Pin Devsy 1.16.2 when warm profile
changes are needed: 1.23.2 rejects a changed `runServices` list as structural.
Do not follow its recreation suggestion on a retained environment. Keep any
explicit `DEVSY_AGENT_BINARY` consistent with the installed Devsy release.

## Validation

1. Run `devrouter -V` from the consumer checkout and confirm 0.5.3.
2. Run `devrouter doctor --json` and inspect runtime ownership and agent readiness.
3. Run `devrouter ensure .` with the consumer's intended profile, then an existing
   smoke or browser test. Do not replay destructive bootstrap hooks for a
   retained database just to test an upgrade.
4. If testing profile changes or stop/resume, verify the exact container and
   volumes are retained. Never bypass lifecycle fences or edit ownership records.

A zombie lifecycle worker retaining its recorded birth identity remains a
known recovery limitation on hosts whose PID 1 does not reap children.

## Report

Report the published version and resolved executable, selected runtime and
version, tested profile and functional outcomes, and any remaining limitations.
