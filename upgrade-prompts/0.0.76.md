# Upgrade to devrouter 0.0.76

This patch accepts canonical-equivalent historical profile selections during
initial managed stop and prevents first-transition rollback from contradicting
captured degraded configuration. No schema, command or flag migration is needed.

## Task

Use the published 0.0.76 CLI. Update `.devrouter.yml` devrouter.version only when
consumer source changes are authorized. Preserve another task's staged work.
Refresh generated agent guidance only with the repository owner's authority.
No generated runtime configuration or journal rewrite is required or authorized.

For an affected exact checkout, its runtime owner uses `devrouter stop <path>
--json` with the original Compose inputs. Canonical-equivalent selections pass
the profile check; every ownership and configuration proof still applies. A
Compose hash refusal must be investigated rather than bypassed. Historical
contradictory generated configuration remains unproved without writer evidence;
a valid retained stop baseline can support containment, not automatic resume.

## Validation

Verify the installed version and exact checkout ownership. Require live provider,
container and route cessation proof for stop. A later ensure needs its own runtime
and readiness proof. New compatible failed-first-transition retries retain matching
configuration; extra resources and manual drift remain refusals. Source tests or a
passed profile check do not establish full consumer recovery.

## Report

Report release revision, installed executable, exact checkout, stop/ensure result
or precise refusal, and source/index preservation. Separate release/install proof
from live consumer acceptance.
