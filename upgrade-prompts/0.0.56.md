# Upgrade to devrouter 0.0.56

Ordinary managed ensure automatically recovers eligible retained degraded runtimes.
Durable lifecycle workers preserve stop precedence and proven command outcomes;
uncertain arbitrary commands are never silently replayed. Current stopped state
is reported separately from historical transition failures.

HTTP proxy apps may declare a readiness path, accepted statuses and content type.
A failed application check reports application-error and exits nonzero while
retaining tools and routes for application repair. Unapplied Compose service edits
no longer prevent exact retained Devsy stop; startup configuration checks remain.

## Task

Install the published patch and update `.devrouter.yml` devrouter.version to
0.0.56. Refresh bundled agent guidance through the existing repository workflow.
No dependency or database migration is required. Adopt application readiness only
for a bounded read-only endpoint that represents the desired application contract:

```yaml
readiness:
  path: /api/health
  statuses: [200]
  contentType: application/json
```

This field applies to HTTP proxy apps. Existing route-only apps keep their prior
behavior. Do not treat route reachability as authenticated journey evidence.

## Validation

On an authorized exact checkout, verify warm ensure, declared application health,
tooling availability after application failure, and non-destructive stop/resume.
Confirm retained synthetic records and generated preparation state where relevant.
After checks, stop the exact runtime and independently verify provider Stopped and
zero exact routes. Preserve data, caches and other environments.

Do not replay unknown commands, remove ownership records, bypass stop fences or
reset data to force readiness. Ordinary ensure owns supported retained recovery;
an agent should not need an explicit repair for eligible degraded state.

## Limits

This release does not activate a machine controller, global capacity admission,
continuous autonomous recovery or coding-harness enrollment. It does not claim
complete OOM protection. Unknown ownership and uncertain execution remain explicit.

## Report

Report installed and configured versions, exact checkout/profile, automatic actions,
application and tooling proof, warm reuse, retained records, final provider/route
state and any unsupported cases. Distinguish synthetic tests from live proof.
