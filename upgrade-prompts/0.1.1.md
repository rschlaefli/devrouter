# Upgrade to devrouter 0.1.1

This is a patch release on top of 0.1.0. It closes one way a managed environment
could sit blocked without saying so: a start that admission refused on a fixed
published host-port claim left the journal recording the intent as `running`
while no runtime existed, so `devrouter status` reported a stable, drifting-free
environment that could not progress.

## What changed for a consumer

- A managed `ensure` refused because a running container already holds a fixed
  published host port now stays visible after the command exits. `devrouter
  status` reports a `start-refused` attention reason with two recovery
  commands: the read-only `devrouter doctor <repo>` check that names the
  conflicting consumer binding and its holder, and the consumer-side fix
  followed by `devrouter ensure <repo>`.
- An explicit `devrouter stop <repo>` releases that intent and the reason, and a
  later admitted ensure clears it. Nothing else about the refusal changed: the
  start is still refused before any provider mutation, and live-worker,
  unknown-ownership and surviving-resource checks still refuse fail-closed.
- The release also carries `pnpm qualify:slow-dependency`, the developer
  qualifier behind the Q06 dependency-recovery evidence. It is a repository
  script and has no consumer-facing effect.

## Task

Use the published 0.1.1 CLI. Update the repository `devrouter.version` metadata
only when consumer source changes are authorized, and refresh generated agent
guidance only with its owner's authority. No schema, command, flag, environment
or journal migration is needed, and the upgrade rewrites no runtime state.

## Validation

Verify the resolved executable and installed version, then run `devrouter
doctor` for the checkout and confirm `global.cli-path` reports one
authoritative install. Run `devrouter status` and confirm the reported intent,
phase and attention reason agree with the runtime you observe. When the reported
reason is `start-refused`, resolve the named binding as the owner of that
port — the shared router is never the side to stop — and keep each lifecycle
operation's own terminal evidence separate from a status block or progress line.

## Report

Report the release revision, the executable and installed version, the status
block for any affected checkout, and the terminal result of any authorized
lifecycle operation. Keep source and package validation separate from consumer
readiness or recovery, and record unknown ownership or surviving resources as
unresolved rather than as recovered.
