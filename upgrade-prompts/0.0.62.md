# Upgrade to devrouter 0.0.62

This patch restores manual tooling access after interrupted preparation has drained,
when the exact retained Devsy runtime can be proven. Each subsequent command keeps
requiring fresh identity proof until a later ensure replaces the interrupted result.
History rollover preserves the latest preparation result.

## Task

Install the published patch through the established workflow and update
`.devrouter.yml` devrouter.version to 0.0.62. No schema migration is required.
Refresh distributed agent guidance through the existing repository workflow.
Do not restart or recreate a retained runtime to test tooling access.

## Validation

Confirm the installed version and exact checkout/provider identity. Run canonical
`devrouter exec <checkout> -- node --version` once on an already-running runtime.
Verify a known completion and unchanged configuration, managed state, routes,
container identity and retained data. Preserve the interrupted ensure result.
Never replay an uncertain command. Continue only already-authorized validation.

## Limits

Recovery requires Devsy with the plain local Docker command and exact ownership
proof. It does not repair missing stop baselines, change provider configuration,
resolve repository bootstrap errors, provide complete OOM protection, enable
capacity admission, or establish autonomous agent recovery. Synthetic qualification
is not live consumer acceptance. Installation alone does not change runtime state.

## Report

Report installed version, exact checkout/provider, command outcome, preservation
checks, remaining limitations and final runtime/route state or existing retention
lease. Distinguish released source from consumer acceptance.
