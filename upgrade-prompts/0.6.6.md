# Upgrade to devrouter 0.6.6

Managed status/doctor recovery commands preserve the exact checkout argument when
paths contain spaces, apostrophes or shell expansion characters. Startup,
failed-transition inspection and nested-mount restart/inspection guidance use
canonical `devrouter` names. Existing variant flags, diagnostic levels and
execution eligibility remain. No configuration schema or lifecycle contract changes.

## Task

Within approved installation/adaptation scope, select the verified exact package,
update `devrouter.version` in `.devrouter.yml` and refresh existing agent guidance
with `devrouter repo agents`. Check every PATH-visible executable and known
wrapper, package/source invocation and harness/controller pin. Obtain participating
owners' actual executable/package identities; PATH inventory is not fleet proof.
Do not start a consumer to validate metadata or installation.

Before the first 0.6.6 lifecycle write, coordinate compatible qualified clients
sharing those journals, including readers and controllers. Older 0.6.5 refuses
newer-writer state through direct reads, updates and global enumeration. Unknown
or competing client identities hold activation. Each receiving host and consumer
retains its runtime/data authority and consumed attempt limits. Installation and
release notices do not authorize activation.

Preserve journal bytes, writer stamps and durable initialization/replacement
receipts. An older reader is not a downgrade recovery route after newer writes.
Use a compatible qualified CLI with fresh ownership proof for authorized recovery;
never edit or erase state or version/hash fences to bypass refusal or rearm attempts.

## Validation

1. Verify selected package integrity, executable bytes/version and existing local
   guidance. Run native checks for actual consumer edits.
2. Treat diagnostic commands as advice subject to existing startup/repair
   preconditions and the receiving owner's runtime authority. Preserve known
   refusals and unknown completion; quoting is not additional eligibility proof.
3. Separately authorized runtime work ends with canonical stop and exact provider,
   container, route and worker proof unless the user explicitly retains it.

## Report

Report exact selected package/executable identities, participating-client adoption,
remaining unknowns, relevant checks and any actual runtime terminal. Keep release
and package proof distinct from consumer recovery. This patch adds no provider
combination, maintenance/reset qualification, consumer-data acceptance or permission
for another runtime attempt.
