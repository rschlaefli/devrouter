# Upgrade to devrouter 0.6.5

Status and doctor now recommend `devrouter ensure <checkout>` for managed
repositories, including profiles with no routed apps. The command quotes the
exact checkout path. Legacy app guidance and existing unwound-mount diagnostics
remain. No configuration schema or provider/lifecycle contract changes.

## Task

Within approved installation/adaptation scope, select the verified exact package,
update `devrouter.version` in `.devrouter.yml` and refresh existing agent guidance
with `devrouter repo agents`. Check every PATH-visible executable and known
wrapper, package/source invocation and harness/controller pin. Obtain participating
owners' actual executable/package identities; PATH inventory is not fleet proof.
Do not start a consumer to validate metadata or installation.

Before the first 0.6.5 lifecycle write, coordinate compatible qualified clients
sharing those journals, including readers and controllers. Older 0.6.4 refuses
newer-writer state, including direct reads, updates and global enumeration.
Unknown or competing client identities hold activation. Each receiving host
and consumer retains its own runtime/data authority and consumed attempt limits.
Installation and a release notice do not authorize activation.

Preserve journal bytes, writer stamps and durable initialization/replacement
receipts. Downgrading an older reader is not a recovery route after newer writes.
Use a compatible qualified CLI with fresh ownership proof for authorized recovery;
never erase or edit state to bypass refusal or rearm an attempt.

## Validation

1. Verify selected package integrity, executable bytes/version and existing local
   guidance. Run native checks for the actual consumer edits.
2. Use canonical exact-checkout ensure only under the receiving owner's separate
   runtime authority. Diagnostic startup guidance is advice, not approval or proof
   that all startup preconditions hold. Retain known refusals and unknown outcomes.
3. Any separately authorized runtime work ends with canonical stop and exact
   provider/container/route/worker proof, unless explicitly retained by the user.

## Report

Report the exact selected package and executable identities, participating-client
adoption and remaining unknowns, relevant checks and any actual runtime terminal.
Keep release/package proof distinct from consumer recovery. This patch's
qualification does not add provider combinations, maintenance/reset support,
consumer data acceptance or permission for another runtime attempt.
