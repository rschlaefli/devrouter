# Upgrade to devrouter 0.2.0

This minor release adds worktree lifecycle tooling.

- `workspace down` is safer.
- A Git-safety verdict covers every linked worktree, managed or not.
- Reclaim and trim commands apply only an approved, hash-bound manifest.
- Two installable skills ship with the release: `worktree-reclaim` and
  `devrouter-setup`.

It adds one optional `.devrouter.yml` key, `worktrees`. Earlier versions reject
unknown keys. A repository that declares `worktrees` therefore needs 0.2.0 or
later on every machine that loads its configuration.

## What changed for a consumer

- `workspace down` refuses to remove a worktree that holds local state the
  earlier check missed. That state covers:
  - unrecognised ignored files;
  - a detached HEAD;
  - an index lock;
  - an unfinished merge, rebase, cherry-pick, revert or bisect;
  - initialized submodules.

  The error names each reason. `--keep-worktree` still removes only the
  runtime and routes.
- `workspace cleanup --all-worktrees --check-merged` reports `RECLAIM`, `KEEP`
  or `PRUNE` with stable reason codes for every linked worktree. This report
  uses schema version 3. Without the flag, the report stays at schema version
  2.
- `workspace reclaim` removes the worktrees in an approved manifest. It removes
  their runtime, ownership record and branch along with each worktree.
- `workspace trim` removes only the ignored paths declared in
  `worktrees.trim` and leaves the worktree, branch and runtime in place.
- Both commands follow the same manifest rules:
  - Both are dry runs until `--yes` is passed.
  - Both re-check each target inside its lifecycle lock.
  - Both write receipts, so a rerun reports `already-done`.
- `cleanup --manifest` emits the manifest, and `workspace manifest hash|select`
  hashes or narrows it. Manifests are interchangeable with the
  `worktree-reclaim` skill.
- `npx skills add rschlaefli/devrouter` installs the `devrouter`,
  `worktree-reclaim` and `devrouter-setup` skills.

## Task

Install the published 0.2.0 CLI. No migration or runtime-state change is
needed.

Optionally declare reproducible ignored paths in `.devrouter.yml`. Do this only
when consumer source changes are authorized. When you add the key, raise the
documented minimum devrouter version to 0.2.0 in the same change:

```yaml
worktrees:
  disposable: ["**/playwright-report"]
  trim: ["**/node_modules", "**/.next"]
```

## Validation

1. Run `devrouter -V` from the consumer checkout. A repository Volta pin can
   change which install resolves.
2. Run `devrouter doctor --repo <checkout>`.
3. Run `devrouter workspace cleanup --repo <checkout> --all-worktrees
   --check-merged` and confirm the report lists every linked worktree with a
   verdict.
4. Run every reclaim or trim as a dry run first. Run with `--yes` only after a
   person has approved the manifest's printed SHA-256.

## Report

Report:

- the release revision;
- the resolved executable and its installed version;
- the verdict counts from the cleanup report;
- for any authorized reclaim or trim, the manifest hash and the per-target
  outcomes.

Report kept trees with their reason codes, never as failures.
