# Upgrade to devrouter 0.6.2

This patch extends managed startup with explicit initialization for a new
disposable environment. Existing configurations and ordinary preserving
startup remain compatible. No reset, data deletion or implicit initialization
is introduced.

## Task

Within an authorized consumer adaptation, install the published CLI, confirm
its executable/version, bump `devrouter.version` in `.devrouter.yml` and refresh
existing agent guidance with `devrouter repo agents`. Update an explicitly
managed controller to the matching version before using the new intent there;
an old controller refuses the new protocol field.

A repository that needs first initialization may declare
`managedRuntime.devcontainer.freshBootstrap` with literal `command` argv,
nonempty `dataVolumes` keys and optional distinct `sharedCaches` keys. For a new
disposable checkout only, request `devrouter ensure <path> --profile <name>
--initialize-new --json`. The repository owns database identity, emptiness,
schema and seed validation. Qualify its original hooks as preserving.

Read `docs/DEVCONTAINER.md` for the supported context and mount requirements.
The initial qualified provider is Devsy 1.19.0 with the default environment
probe. Non-cache volumes must use new local storage; declared shared caches
must be external. Unsupported contexts and unknown ownership refuse.

An initialization request durably consumes one attempt before provider
creation. Failure, cancellation and unknown completion retain partial data and
the attempt. Stop, replacement, registration loss and journal settlement never
rearm it. Use supported preserving recovery, or a new disposable checkout for
a new attempt. Never hand-edit its journal, infer reset authority or bypass
worker, ownership, endpoint or population refusals.

## Validation

1. Run the consumer's static configuration and bootstrap checks for actual edits.
2. When runtime verification is authorized, initialize a new disposable fixture
   with the explicit flag, verify actual application work and exact synthetic
   data through stop/resume and the intended replacement path, and confirm a
   second initialization request refuses.
3. Verify failure/unknown completion preserves data and prevents replay. Finish
   with canonical `devrouter stop <path>` and prove stopped provider state and
   zero exact routes unless the user explicitly keeps it running.

## Report

Report exact source/package/executable identities, changed configuration,
qualified provider/context and tests, initialization/preserving behavior,
actual retained-data evidence, remaining consumer prerequisites and final
provider/route state. A release or installation alone is not consumer recovery.
