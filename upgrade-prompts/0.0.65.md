# Upgrade to devrouter 0.0.65

This feature release adds managed-workspace network capacity support: read-only
capacity and retained-ownership diagnostics plus opt-in daemon-bound subnet
allocation for new managed linked-workspace Compose networks.

## Task

Install the published release and update `.devrouter.yml` devrouter.version to
0.0.65. No schema migration is required. Opting a repository in needs two
operator steps: install `~/.config/devrouter/network-policy.json` naming
private pools, exclusions and permitted prefixes for the exact Docker daemon,
then add `managedRuntime.network` to the repository configuration. Repository
configuration cannot select address ranges. Adding a policy changes nothing for
existing workspaces, networks or provider registrations.

## Validation

Run `devrouter doctor --repo <checkout> --json` and confirm the read-only
network capacity report. On an authorized runtime with a valid policy, start a
new managed linked workspace and verify the ignored generated Compose overlay,
the persisted subnet claim, exact provider destination reuse, and subnet
retention across stop and resume. Verify failure paths retain claims and never
delete networks, containers or workspaces. Stop the exact runtime afterwards
and confirm zero routes with retained data.

## Limits

Allocation requires complete route and daemon evidence; virtualized contexts
such as OrbStack stay diagnostics-only until guest routes are qualified.
Existing `/24` networks are never subdivided or migrated. Stopping a workspace
or removing its worktree does not release a subnet, and cleanup remains
report-only. Without a policy, allocation behavior is unchanged.

## Report

Report installed version, policy presence without its contents, diagnostic
output, allocation outcomes with synthetic receipts, and any retained claims or
resources. Separate published source, synthetic checks and live runtime proof.
