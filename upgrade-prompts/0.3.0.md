# Upgrade to devrouter 0.3.0

This minor release finishes worktree cleanup after deleted checkouts and adds
a team guide.

- `workspace gc` can now remove a Devsy workspace whose checkout folder was
  already deleted.
- `workspace cleanup --all-worktrees` lists Docker leftovers: the Compose
  stacks of deleted worktrees.
- `workspace leftover` removes approved leftovers from a hash-bound manifest.
- `docs/WORKTREE_CLEANUP.md` explains the whole cleanup flow for engineers.

There is no configuration change and no migration.

## What changed for a consumer

- When the ordinary Devsy delete fails, `gc` forces it only when the recorded
  folder no longer exists and the runtime is stopped or not found. A failed
  delete of a folder that still exists is reported, never forced.
- The cleanup report gains a `dockerLeftovers` section with schema version 3.
  A stack counts as a leftover only when all of its containers name the same
  folder below `<repo>/trees/`, at least one container was created by DevPod
  or Devsy, the folder no longer exists, it is not inside another existing
  worktree, no registration still names it, and every container is stopped.
  Blocked stacks name the next step (`workspace gc` or `git worktree prune`).
- `workspace cleanup --manifest --action leftover --output <file>` writes a
  `docker-leftover-manifest`. `workspace leftover --manifest <file> --sha256
  <hash>` is a dry run until `--yes`. It removes the listed containers, then
  the listed volumes (project and anonymous volumes no other container uses),
  then networks, and skips any stack that changed.
- Volumes that no container ties to a deleted worktree are reported and never
  removed. Worktree `reclaim` and `trim` reject leftover manifests.

## Task

Install the published 0.3.0 CLI. No migration or runtime-state change is
needed. Raise a repository's documented minimum devrouter version to 0.3.0
only when consumer source changes are authorized and the team should use the
leftover commands.

## Validation

1. Run `devrouter -V` from the consumer checkout. A repository Volta pin can
   change which install resolves.
2. Run `devrouter workspace cleanup --repo <checkout> --all-worktrees` and
   confirm the report includes the Docker leftovers section.
3. Run `devrouter workspace gc` and every leftover removal as a dry run first.
   Run with `--yes` only after a person has approved the exact targets or the
   manifest's printed SHA-256.

## Report

Report:

- the release revision;
- the resolved executable and its installed version;
- the leftover and blocked counts from the cleanup report;
- for any authorized gc or leftover removal, the targets or manifest hash and
  the per-target outcomes.
