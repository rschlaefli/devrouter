# Upgrade to devrouter 0.0.63

This patch waits for healthy lifecycle workers before tooling execution and
recovers stop when a saved baseline proves a linked Devsy runtime absent.

## Task

Install the published patch through the established workflow and update
`.devrouter.yml` devrouter.version to 0.0.63. No schema migration is required.
Refresh distributed agent guidance through the existing repository workflow.
Installation does not require a runtime restart.

## Validation

Confirm the installed version and exact checkout/provider identity. On an
already-running authorized runtime, run canonical `devrouter exec <checkout> --
node --version` and verify completion without restarting services. Never replay
an uncertain command. For an already-authorized absent-runtime recovery, use
canonical `devrouter stop <checkout> --json`; verify stopped state, zero scoped
routes and retained history. Run ensure only within the consumer owner's scope.
A successful stop does not prove that subsequent startup succeeds.

## Limits

Absent-runtime recovery requires a valid saved baseline, exact linked-workspace
ownership and Devsy selection. It does not override mixed-provider selection,
repair legacy records without baselines, solve exhausted Docker network pools,
enable capacity admission or provide complete OOM protection or autonomous agent
recovery. Host process-inspection restrictions still require permitted host
execution; never remove locks or weaken ownership checks to work around them.

## Report

Report installed version, exact checkout/provider, command outcome, preservation
checks and final runtime/route state or explicit retention requirement. Separate
released source, synthetic checks and live consumer acceptance.
