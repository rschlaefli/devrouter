# Upgrade to devrouter 0.6.9

`devrouter exec` on a Devsy runtime now addresses the exact running workspace
container. Devsy then starts the command in the container's configured
`workspaceFolder`. Before, Devsy resolved a workspace addressed by name to
`/workspaces/<workspace-id>` and ignored a Compose-based devcontainer's
`workspaceFolder`, so `exec` failed with a `chdir` error for any repository
whose folder differs from that default. No configuration schema, command
surface, dependency, ownership, admission or lifecycle-journal format changes
are introduced.

## Task

Within approved installation/adaptation scope, select the integrity-verified
exact package, update `devrouter.version` in `.devrouter.yml` and refresh
existing agent guidance through `devrouter repo agents`. No consumer
configuration change is required.

## Validation

1. Verify registry integrity and the selected executable version.
2. With an already running managed Devsy workspace, run
   `devrouter exec <checkout> -- pwd` and confirm it prints the configured
   `workspaceFolder`.
3. Any separately authorized runtime work ends with canonical stop unless the
   user keeps it running.

## Report

Report the selected package and executable identity and the `exec` check
result. Installation alone grants no consumer startup, repair, reset or
replacement authority.
