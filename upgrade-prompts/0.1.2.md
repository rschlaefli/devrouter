# Upgrade to devrouter 0.1.2

This is a patch release on top of 0.1.1. It carries the post-release reliability
review corrections: truthful recovery guidance, a harness gate that honors its
full wait budget and recognizes its own lifecycle commands in every supported
invocation form, evidence-accurate hook wording, bounded cause-and-location
diagnostics for unprovable capacity history, and a content-digest fence on
capacity snapshot replacement.

## What changed for a consumer

- The recovery line a refused managed start prints now reads `devrouter doctor
  --repo <checkout>` (single-quoted when the path needs it) instead of a
  positional path that `doctor` never accepted. Stored guidance that quotes the
  old form should be refreshed.
- The harness gate (`devrouter harness gate`, wired as a PreToolUse hook) now
  recognizes `devrouter` lifecycle commands as direct executables and through
  the `npx`, `pnpm exec`, `npm exec` and `yarn` launchers, including
  `env` and assignment prefixes. During a transition, `devrouter status`,
  `stop` and `ensure` reach their own bounded checks instead of being deferred
  or refused as unrelated calls. Unrelated calls still defer or refuse as
  before.
- A gated call under a budget now waits the whole budget: the gate observes once
  more at the deadline instead of refusing early when the next poll interval
  would overrun it.
- Hook output no longer reports "environment settled" for passthrough,
  unmanaged, invalid-payload or unavailable evidence; each decision says what it
  actually observed.
- `devrouter doctor` names the bounded cause and the exact journal entry when
  capacity history is unprovable, and the network-capacity check names the
  missing evidence inputs, so the operator can act without guessing.

## Task

Use the published 0.1.2 CLI. Refresh consumer-side guidance that quotes the old
positional recovery command, and update the repository `devrouter.version`
metadata only when consumer source changes are authorized. No schema, command,
flag, environment or journal migration is needed, and the upgrade rewrites no
runtime state.

## Validation

Verify the resolved executable and installed version with `devrouter -V`, then
run `devrouter doctor --repo <checkout>` and confirm `global.cli-path`
reports one authoritative install. For an environment whose harness hook uses
`devrouter harness gate`, run one gated lifecycle command during a transition
and confirm it reaches its own check. When `doctor` reports unprovable capacity
history, follow the named cause-keyed recovery instead of deleting journal
state.

## Report

Report the release revision, the executable and installed version, the doctor
block for any affected checkout, and the terminal result of any authorized
lifecycle operation. Keep source and package validation separate from consumer
readiness or recovery, and record unknown ownership or surviving resources as
unresolved rather than as recovered.
