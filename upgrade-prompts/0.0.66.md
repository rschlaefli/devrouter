# Upgrade to devrouter 0.0.66

This patch release completes managed stop when Devsy replaces a workspace
registration UID after the workload is positively absent, releasing lifecycle
journals stuck in `stopping` so a later `ensure` is admitted again.

## Task

Install the published release and update `.devrouter.yml` devrouter.version to
0.0.66. No schema migration or configuration change is required. Do not change
the committed configuration, delete registrations, containers, or source files,
and do not reset lifecycle state manually: the recovery runs inside the existing
canonical stop command under its normal locks and proofs.

## Validation

On a workspace whose stop was previously rejected with a retained provider
identity error after a registration replacement, run the canonical
`devrouter stop <path>` and confirm it reports the workspace stopped with the
absence proof, then run `devrouter ensure <path>` and confirm admission
succeeds. Confirm `devrouter status --json` shows the expected ready state and
that no containers, volumes, or source files were removed beyond the normal
stop contract. For workspaces that never hit the replacement case, confirm
existing stop, ensure, and `devrouter doctor` behavior is unchanged.

## Report

Report the tested CLI version, the exact workspace path or synthetic fixture,
the stop command result, the ensure result, route state after the run, and any
diagnostic failure output verbatim. State explicitly whether the replacement
case was exercised or only the unchanged retained path.
