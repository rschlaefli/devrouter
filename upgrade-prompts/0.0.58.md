# Upgrade to devrouter 0.0.58

This patch permits recovery directly into a different requested profile after
retained ownership proof. Failed processes excluded by that profile no longer
have to start first. Failed transitions preserve degraded evidence and data.

## Task

Install the published patch and update `.devrouter.yml` devrouter.version to
0.0.58 through the consumer repository workflow. No database migration is needed.
Refresh generated agent guidance when the repository distributes it.

Repositories that generate Compose inputs before inspection may configure
`managedRuntime.devcontainer.prepareCommand` as a literal argv array. The command
runs on the host in the checkout root, once per ensure, with a sixty-second bound.
Keep it in the foreground, preserve `.devrouter.yml`, and leave diagnostics
read-only. Output is suppressed; report failures through the command exit status.

## Validation

Resolve the intended profile and ensure only an authorized exact checkout. For
degraded recovery, verify the requested resources start without replaying excluded
processes. Verify host preparation before Compose inspection using a repository
generator whose output can be checked without exposing values. Separate successful
generation from applying changed mounts to an existing container.

Check application readiness and tooling separately. Retain data and stop only
task-owned runtimes, then verify stopped provider status and zero exact routes.

## Limits

This release does not implement warm mount reconciliation, capacity admission,
controller observation, autonomous agent recovery or complete OOM protection.
Ownership conflicts remain actionable errors; they never authorize destructive
repair or changing another task's runtime.

## Report

Report installed/configured versions, exact checkout and profile, preparation
result, requested-profile recovery evidence, application/tooling outcomes and
final runtime status. Identify any remaining unverified consumer behavior.
